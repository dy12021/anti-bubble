fix: 用户实测反馈的三个问题——收藏/点赞没读到、首页误屏蔽、引战没屏蔽

用户在自己的 Edge 上实测，反馈三件事。查下来根因都不小：

**① 「系统没有读取我的收藏和点赞」——收藏夹这一路一直是坏的**
- `/x/v3/fav/folder/created/list-all` **必须带 `up_mid`**，漏了就返回 -400。
  看起来像「没有收藏」，其实是「参数不对」——收藏夹从来没被读到过。
- 收藏夹内容的 id 参数名是 **`media_id`**，我们写的是 `fid`。
- `/x/relation/followings` **必须带 `vmid`**，关注列表同理。
- 观看历史的返回形状新版换成了 `data.list.vlist`（对象），老代码按数组用，
  `push(...非数组)` 直接抛异常 → **把整轮采集中断** → 样本 0 条。
  现在两种形状都兼容，而且**每个源单独 try/catch**：一个源坏了不会拖垮其它源。

**② 「系统在首页屏蔽的是我喜欢的内容」——没有画像时不该替用户猜**
用户看到的折叠理由是「内容是Minecraft工具问题，**与AI立场无关**」。
那条只是**跑题**，不是**用户不喜欢**。
根因：没有画像时，「用户大概率不喜欢」没有依据，模型就拿
「当前页面/视频的主题」当了替身 → 跑题即折叠。
现在没有画像（或画像空空）时**只折叠明确的引战**，
prompt 里写死「跑题不是折叠理由」。
实测：首页 10 条判定**全 pass、0 折叠**（之前会误伤）。

**③ 「有的引战视频反而没有屏蔽」——词表是召回闸门，判据没覆盖就永远进不了精判**
两个页面的词表 prompt 现在都要求判据里**必须有一批引战类**表达
（骂人、攻击群体/地区/国籍、嘲讽特定人群、煽动对立），
并明确「写成会原样出现的词，别写成行为描述」。

**顺带**：面板上新增「采集来源」一行（观看历史 N / 收藏夹 N / 点赞 N / 关注 N /
我的投稿 N，没通的打 ✗，鼠标悬停有原因）。
0 条样本时用户分不清「没登录」「接口坏了」「这个源本来没数据」——
现在一眼就看到是哪一路不通。采集报告**即使 0 条也回传**（早先「0 条就 return」
把最有用的诊断信息一起吞了）。
